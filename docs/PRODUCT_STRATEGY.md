# OlyHub Commercial Product Strategy

## North star

OlyHub is not sold as "a better base model than ChatGPT, Claude or Gemini."

It wins by becoming the place where the user's work already lives and keeps moving.

The habit loop is:

1. Open OlyHub.
2. Zeus knows the active project and recent decisions.
3. The user asks, uploads, researches, builds or decides.
4. The result becomes a durable conversation, task, file, artifact or memory.
5. The user returns to the same state instead of rebuilding context somewhere else.

## Product hierarchy

### Zeus — default daily mode
Zeus is the product's default interface.

It should feel fast enough for ordinary questions and smart enough to route harder work without the user managing providers.

Target: one strong lead route with failover across the other configured providers, plus a reviewer only when expected value justifies the extra latency/cost.

### Olympus — deliberate mode
Olympus exists for work where independent perspectives materially improve the result: architecture, consequential decisions, audits, research synthesis and complex plans.

It must not be a cosmetic multi-model mode. If it cannot show meaningful specialist disagreement, validation or integration, it should degrade to Zeus rather than simulate a council.

## Durable moat

Priority order:

1. Projects with persistent conversations and files.
2. Useful scoped memory with provenance and controls.
3. Artifacts the user can reopen, version and continue editing.
4. Tasks and execution traces attached to the project.
5. Search across the user's own OlyHub work.
6. Cross-device/mobile continuity.
7. Provider orchestration behind one stable OlyHub identity.

The provider is infrastructure. OlyHub owns the workflow, context, permissions and continuity.

## Non-goals

- Do not market raw model routing as the main product.
- Do not expose provider complexity unless it helps trust or control.
- Do not claim Olympus used multiple models unless multiple independent routes actually ran.
- Do not copy private Zeus Proxy memory, credentials or unrestricted permissions into the commercial product.
- Do not build decorative features that do not increase repeated use, trust, or completed work.

## Retention test

Every major feature should answer at least one of these:

- Does this save context the user would otherwise have to repeat?
- Does this keep work moving after the chat response?
- Does this produce something durable the user will reopen?
- Does this reduce the need to switch to another AI app?
- Does this make OlyHub more trustworthy or easier to use daily?

If the answer is no to all five, it is probably not a priority.
